## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
‘플라워샵 근무 관리’는 여러 플라워샵의 직원 가입, 출퇴근 기록, 급여 계산을 관리하는 웹 프로그램입니다. 급여 방식은 **시급** 또는 **월급** 중 하나이며, 급여 방식과 금액은 적용 시작일을 기준으로 계산합니다.

### 역할
1. **시스템 관리자**: 플라워샵을 등록하고 이름을 수정합니다.
2. **플라워샵 관리자**: 본인 플라워샵의 직원 가입을 승인하고, 직원 상태·급여 조건·근무 기록·월별 정산을 관리하며, 로그인 화면에서 본인 정보(이름, 비밀)를 직접 수정할 수 있습니다.
3. **플라워샵 직원**: 가입을 신청하고, 승인되어 재직 중일 때 본인의 근무 기록과 급여 내역을 조회·관리합니다. (직원 로그인 대상에서 대표 관리자는 완전히 제외됩니다.)

### 핵심 동작 규칙
- 모든 화면 상단에 ‘플라워샵 근무 관리’ 프로그램 배너를 구성하고 현대적이고 세련된 카드 레이아웃을 적용합니다.
- 인증 및 보안 관련 입력 라벨은 ‘비밀’, ‘비밀 확인’으로 표시합니다.
- 메인 화면 상단 배너 바로 아래에 ‘플라워샵 관리’ 버튼을 배치하고, 하단에 별도 영역으로 지정된 플라워샵 목록에서 ‘선택’ 버튼을 눌러 해당 플라워샵으로 이동합니다.
- 시스템 관리자가 없으면 `/system-setup`에서 최초 계정을 만들고, 계정이 이미 있으면 해당 화면에서 로그인합니다.
- 플라워샵별 관리자 정보는 해당 `shop_id`만 기준으로 조회합니다.
- 직원 상태는 `pending`(승인 대기), `active`(재직), `resigned`(퇴사)로 관리합니다. 재직 직원만 근무 기록을 추가·수정할 수 있고 직원 로그인 목록에도 재직 직원만 표시합니다. (대표 관리자는 직원 로그인 대상에 포함되지 않습니다.)
- 시급 직원은 날짜별 근무 기록으로 급여를 계산합니다. 월급 직원은 월 고정액을 기준으로 일할 계산하며 출퇴근 기록 입력 기능을 사용하지 않습니다.
- 모든 급여는 원 단위로 반올림합니다. 휴게 시간은 차감하지 않습니다.
- **중요 보안 규칙**: 브라우저 클라이언트에서 Supabase 테이블에 직접 `INSERT`/`UPDATE`/`DELETE`를 수행하면 RLS 정책(`42501`) 오류가 발생합니다. 모든 쓰기 작업은 반드시 Next.js Server Actions 또는 Route Handler에서 `SUPABASE_SERVICE_ROLE_KEY`를 사용하는 서버 전용 클라이언트로 처리합니다.

## 2. 사용자와 사용 시나리오

### 사용자 역할 및 권한

| 역할 | 인증 | 허용되는 작업 |
| --- | --- | --- |
| 시스템 관리자 | 이름 + 숫자 4자리 ‘비밀’ | 전체 플라워샵 조회, 등록, 이름 수정 |
| 플라워샵 관리자 | 플라워샵 선택 + 관리자 이름 + 숫자 4자리 ‘비밀’ | 소속 플라워샵 직원 신청 승인, 재직·퇴사 상태 변경, 급여 유형·금액·적용 시작일 관리, 소속 직원 근무 기록 보완, 월별 정산 조회, **로그인 화면에서 본인 정보(이름, 비밀) 수정** |
| 플라워샵 직원 | 플라워샵 선택 + 본인 이름 + 숫자 4자리 ‘비밀’ | 가입 신청, 재직 상태일 때 본인 출퇴근 기록 추가·수정, 본인 월별 근무·급여 조회, 본인 ‘비밀’ 변경 *(대표 관리자는 직원 로그인 대상에서 완전히 제외)* |

### 사용 흐름
1. 시스템 관리자가 없는 첫 방문은 시스템 관리자 최초 등록 화면으로 안내합니다.
2. 시스템 관리자는 메인 화면의 ‘플라워샵 관리’에서 인증한 뒤 플라워샵을 등록하거나 이름을 수정합니다.
3. 사용자가 메인 화면에서 플라워샵을 ‘선택’합니다. 해당 플라워샵에 관리자가 없으면 관리자 등록을 시작할 수 있고, 관리자가 있으면 관리자 로그인(본인 정보 수정 포함)과 직원 기능을 사용할 수 있습니다.
4. 직원은 플라워샵별 가입 신청을 합니다. 관리자는 신청자를 승인하면서 급여 유형, 금액, 적용 시작일을 설정합니다. 승인 이후 직원 상태는 재직이 됩니다.
5. 시급 직원은 날짜별 출근·퇴근 시각을 등록합니다. 월급 직원은 출퇴근을 입력하지 않습니다. 관리자는 직원별 상세 내역과 월별 지급액을 확인하고 필요하면 근무 기록을 보완합니다.
6. 퇴사 처리된 직원 및 대표 관리자는 직원 로그인 선택 목록에서 제외되고, 과거 기록과 정산 내역은 유지됩니다.

## 3. 기능 명세

### 기능 명세

| ID | 기능 | 동작 규칙 | 수용 기준 (Given/When/Then) |
| --- | --- | --- | --- |
| F-01 | 시스템 관리자 최초 등록 및 로그인 | 시스템 관리자가 없을 때 이름과 동일한 숫자 4자리 비밀 확인값을 받아 생성합니다. 이미 있으면 새로 만들지 않고 로그인을 제공합니다. 서버 액션을 통해 서비스 롤로 저장하여 RLS(42501)를 방지합니다. | **Given** 시스템 관리자가 0명이다. **When** 유효한 이름과 일치하는 숫자 4자리 비밀을 제출한다. **Then** 계정이 한 개 생성되고 로그인 상태가 된다. **Given** 관리자가 이미 있다. **When** 다른 사용자가 최초 등록을 시도한다. **Then** 두 번째 계정은 생성되지 않는다. |
| F-02 | 플라워샵 관리 | 시스템 관리자 인증 후 플라워샵을 등록하거나 기존 이름을 수정합니다. 서버 액션으로 처리합니다. | **Given** 시스템 관리자로 인증했다. **When** 유효한 플라워샵 이름을 저장한다. **Then** 메인 목록에 반영된다. **When** 같은 이름을 등록한다. **Then** 저장하지 않고 ‘이미 등록된 플라워샵 이름입니다.’를 표시한다. |
| F-03 | 플라워샵 검색 및 선택 | 검색어는 이름에 포함되는지 기준으로 찾고, 앞뒤 공백을 제거하며 대소문자 구분 없이 처리합니다. | **Given** 플라워샵이 등록되어 있다. **When** 검색어를 입력한다. **Then** 이름에 검색어가 포함된 항목만 보인다. **When** ‘선택’을 누른다. **Then** 해당 플라워샵의 `/shop/[id]`로 이동한다. 결과가 없으면 ‘검색 결과가 없습니다.’가 표시된다. |
| F-04 | 플라워샵별 관리자 등록·수정 | 관리자 조회·저장 때 현재 플라워샵의 `shop_id`를 반드시 사용합니다. 한 플라워샵에는 관리자 한 명만 둡니다. 서버 액션을 통해 저장하여 RLS 오류를 방지합니다. | **Given** 플라워샵에 관리자가 등록되어 있다. **When** 관리자 로그인 화면에서 본인 정보 수정 기능을 통해 새 이름이나 비밀을 입력한다. **Then** 해당 플라워샵 관리자 정보가 정상 수정된다. |
| F-05 | 직원 가입 신청 | 직원은 이름과 숫자 4자리 비밀 및 확인값으로 신청합니다. 신청 직후 상태는 `pending`이고 로그인은 허용하지 않습니다. | **Given** 플라워샵을 선택했다. **When** 유효한 가입 정보를 제출한다. **Then** 해당 플라워샵에 `pending` 직원이 생성되고 완료 안내가 표시된다. 이름이 이미 사용 중이면 ‘이미 등록된 이름입니다.’를 표시하고 저장하지 않는다. |
| F-06 | 직원 승인·상태 관리·급여 조건 | 관리자는 신청자를 승인할 때 급여 유형(`hourly` 또는 `monthly`), 금액, 적용 시작일을 지정합니다. 직원은 `active`로 전환됩니다. 재직 직원을 퇴사 처리하면 `resigned`가 됩니다. | **Given** 승인 대기 직원이 있다. **When** 관리자가 유효한 급여 조건을 설정하고 승인한다. **Then** 직원 상태가 `active`가 되고 급여 조건이 저장된다. **When** 관리자가 재직 직원을 퇴사 처리한다. **Then** 상태가 `resigned`가 되고 로그인 목록에서 제외된다. |
| F-07 | 직원 로그인 및 비밀 변경 | 로그인 목록은 선택한 플라워샵의 `active` 직원만 보여주며, **대표(관리자) 계정은 직원 로그인 목록에서 완전히 제외**합니다. 인증은 서버에서 해시를 비교합니다. | **Given** 한 플라워샵에 재직 직원과 대표 관리자가 있다. **When** 직원 로그인 목록을 연다. **Then** 재직 직원만 보이고 대표 관리자는 표시되지 않는다. |
| F-08 | 시급 직원 출퇴근 기록 | 시급 재직 직원은 날짜, 출근 시각, 퇴근 시각을 입력·수정합니다. 날짜 기본값은 오늘입니다. 한 직원은 날짜별 기록을 하나만 가집니다. | **Given** 시급 재직 직원이 로그인했다. **When** 09:30~18:30을 저장한다. **Then** 540분으로 계산되어 보인다. **When** 퇴근 시각이 출근 시각과 같거나 빠르다. **Then** 저장하지 않고 ‘퇴근 시간은 출근 시간보다 늦어야 합니다.’를 표시한다. |
| F-09 | 직원의 월별 조회 | 직원은 월 선택으로 본인의 해당 월 근무 기록, 총 근무 시간, 예상 급여를 조회합니다. 월급 직원은 출퇴근 기록 없이 월 급여만 조회합니다. | **Given** 직원이 로그인했다. **When** 정산 월을 선택한다. **Then** 본인 데이터만 해당 월 기준으로 표시된다. 다른 직원 데이터는 응답에 포함되지 않는다. |
| F-10 | 관리자 월별 정산 및 기록 보완 | 관리자는 월을 선택하고 직원별 상태, 급여 유형, 총 근무 시간, 급여액을 확인합니다. 직원을 선택하면 하단 상세 내역이 보입니다. 월급 직원 상세 내역에는 출근·퇴근 항목을 표시하지 않습니다. | **Given** 관리자가 정산 화면에서 월과 직원을 선택했다. **When** 상세를 확인한다. **Then** 해당 직원의 월 기록과 계산 내역이 표시된다. 월급 직원이면 출근·퇴근 항목이 없다. **When** 관리자가 유효한 시급 직원 근무 기록을 저장한다. **Then** 상세 내역과 합계가 갱신된다. |
| F-11 | 공통 배너 및 화면 문구 | 모든 화면 상단에 ‘플라워샵 근무 관리’를 표시합니다. 화면에 보이는 인증 라벨은 ‘비밀’, 확인 라벨은 ‘비밀 확인’입니다. | **Given** 사용자가 어떤 경로를 연다. **When** 화면이 표시된다. **Then** 공통 배너가 보이고, 사용자에게 표시되는 인증 문구에 ‘PIN’이 쓰이지 않는다. |
| F-12 | 입력 오류와 데이터 접근 제한 | 필수값 누락, 잘못된 날짜·금액·비밀, 권한 없는 요청은 저장하지 않습니다. 오류는 해당 화면에 한글 안내로 표시하며 입력값은 유지합니다. | **Given** 사용자가 다른 플라워샵의 직원·근무 기록을 요청한다. **When** 서버가 요청을 검증한다. **Then** 응답은 거부되고 다른 플라워샵 데이터가 반환되지 않는다. 잘못된 입력은 저장되지 않고 원인을 설명하는 안내가 표시된다. |

## 4. 가정과 기본값 (AI가 대신 정한 것)

### 가정과 확정 기본값

| 항목 | 선택한 값 | 이유 | 바꾸려면 |
| --- | --- | --- | --- |
| 급여 유형 | 시급 또는 월급 중 하나 | 기존 요청에서 두 급여 유형과 각각의 정산을 요구함 | 급여 유형 추가 요청 |
| 월급의 월 중간 적용 | 적용된 달력 일수 기준으로 일할 계산 | 적용 시작일이 월 중간인 월급 조건을 일관되게 계산하기 위해 | 일할 계산 방식 변경 요청 |
| 휴게 시간 | 차감하지 않음 | 출퇴근 시간 그대로 계산하기로 확정됨 | 휴게 시간 입력·차감 규칙 요청 |
