## 1. 테스트 계획

### 수용 테스트 시나리오 및 검증 항목

- **테스트 1: 시스템 관리자 최초 등록 강제 리다이렉트**
  - **Given**: `system_admins` 테이블에 등록된 레코드가 0건이다.
  - **When**: 사용자가 사이트 루트(`/`)에 접속한다.
  - **Then**: 즉시 `/system-setup` 화면으로 자동 이동하며, PIN 일치 검증을 통과해야 첫 시스템 관리자가 생성되고 메인 화면으로 이동한다.

- **테스트 2: 플라워샵 대표 등록 버그 해결 (매장 격리 검증)**
  - **Given**: 플라워샵 A에는 이미 대표 관리자가 등록되어 있고, 새로 생성한 플라워샵 B에는 대표가 없다.
  - **When**: 사용자가 플라워샵 B의 허브(`/shop/B`)에서 [대표 관리자 등록]을 눌러 `/admin/setup?shop_id=B`에 진입한다.
  - **Then**: "이미 해당 플라워샵에 관리자가 존재합니다" 오류가 뜨지 않고, 정상적인 빈 등록 폼이 노출되어 대표 계정을 생성할 수 있다.

- **테스트 3: 직원 가입 신청 및 대표 승인 워크플로우**
  - **Given**: 직원이 `/signup?shop_id=A`에서 이름과 4자리 PIN을 입력하여 가입을 신청했다.
  - **When**: 해당 직원이 바로 출근 화면 로그인을 시도한다.
  - **Then**: `status`가 `pending`이므로 "대표의 승인이 필요한 계정입니다" 경고가 발생하며 진입이 차단된다.
  - **When**: 플라워샵 대표가 `/admin`에서 해당 직원의 시급을 11,000원으로 설정하고 [승인] 버튼을 누른다.
  - **Then**: 직원의 상태가 `active`로 변경되고, 즉시 출근 등록이 가능해진다.

- **테스트 4: 출퇴근 기록 및 월급 계산 정합성**
  - **Given**: 승인된 직원이 09:00에 출근하고 18:00에 퇴근을 기록했다 (총 9시간 = 540분, 시급 11,000원).
  - **When**: 직원 마이페이지(`/employee/dashboard`)와 대표 관리자 정산 화면(`/admin/attendance`)을 조회한다.
  - **Then**: 양쪽 모두에서 해당 일자의 근무시간 9시간 00분과 예상 급여 99,000원이 정확히 일치하여 표시된다.
