## 1. 테스트 계획

### 공개 Smoke 경로
- `GET /`
- `GET /system-setup`
- `GET /shop/register`
- `GET /admin/setup`
- `GET /signup`

### 기능 테스트 시나리오
1. **배너 및 메인 화면 구성** — **Given** 메인 화면 접속. **When** 화면을 렌더링한다. **Then** 상단 배너, 배너 바로 아래 ‘플라워샵 관리’ 버튼, 별도 영역으로 지정된 플라워샵 목록과 ‘선택’ 버튼이 올바르게 표시된다.
2. **시스템 관리자 최초 등록 (RLS 우회 검증)** — **Given** 시스템 관리자 0명. **When** 이름과 숫자 4자리 ‘비밀’을 제출하여 서버 액션을 호출한다. **Then** 오류 없이 관리자가 생성되고 로그인된다.
3. **플라워샵별 관리자 독립성 및 본인 수정** — **Given** 플라워샵 A에는 관리자가 있고 B에는 없다. **When** 관리자 로그인 화면에서 본인 정보 수정 기능을 사용한다. **Then** 해당 관리자 정보가 안전하게 수정된다.
4. **직원 가입 및 승인 (대표 제외)** — **Given** 직원이 가입을 신청한다. **When** 관리자가 급여 유형과 금액, 적용 시작일을 설정하여 승인한다. **Then** 직원 상태가 `active`로 변경되고 로그인할 수 있으며, 대표 관리자는 직원 로그인 목록에 나타나지 않는다.
5. **시급 및 월급 정산** — **Given** 시급 또는 월급 직원. **When** 관리자가 정산 월을 선택하고 직원을 선택한다. **Then** 시급 직원은 출퇴근 및 근무 시간 내역이 보이고, 월급 직원은 일할 계산된 급여가 표시되며 출퇴근 항목은 제외된다.
6. **문구 검증** — **Given** 모든 인증 및 화면 요소를 확인한다. **Then** ‘PIN’ 단어 대신 ‘비밀’ 문구가 사용되었음을 확인한다.

## 2. 배포와 운영

### 배포 절차
1. GitHub 저장소의 `main` 브랜치를 Vercel 프로젝트에 연결합니다. `main`에 푸시하면 Vercel이 빌드·배포합니다.
2. Supabase에서 `supabase/migrations/0001_initial_schema.sql`을 적용합니다. 모든 테이블에 RLS가 활성화되었는지 확인합니다.
3. Vercel 환경 변수에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `APP_SESSION_SECRET`을 설정합니다. 서비스 롤 키와 세션 비밀은 서버 환경 변수로만 둡니다.
4. `.env.local`과 키가 포함된 파일을 GitHub에 올리지 않습니다. `.env.example`에는 변수명만 기록하고 실제 값을 쓰지 않습니다.
5. 배포 완료 후 `meta.smokeRoutes`의 경로가 각각 HTTP 200을 반환하는지 확인합니다. 이 경로는 로그인이나 DB 데이터 없이도 페이지 틀을 렌더링해야 합니다. 데이터 조회 실패 시에도 서버 오류 페이지 대신 화면 안에 재시도 안내를 표시합니다.

### 운영 시 확인 사항
- Supabase의 무료 사용 한도와 DB 백업·보존 정책을 운영 전에 확인합니다.
- 시스템 관리자 최초 등록은 동시에 두 요청이 들어와도 한 계정만 만들어지도록 서버에서 다시 확인하고, 생성 작업을 원자적으로 처리합니다.
- 세션 비밀을 교체하면 기존 세션은 만료되어 다시 로그인해야 합니다.
