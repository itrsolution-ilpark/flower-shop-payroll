## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
‘플라워샵 근무 관리’는 다수의 플라워샵에 대해 **시스템 관리자**, **플라워샵 관리자(대표)**, **플라워샵 직원**의 3단계 권한을 엄격히 분리하여, 직원의 가입 신청 및 승인, 일별 출퇴근 등록, 시급/월급 기반 급여 계산, 모바일 최적화 UI, 그리고 정산 내역 CSV 다운로드 기능을 제공하는 종합 업무 웹 프로그램입니다.

### 사용자 역할 및 주요 권한
1. **시스템 관리자 (2명 이상 등록 가능, 비밀번호 숫자 6자리)**
   - 프로그램 전체 총괄 관리 및 추가 시스템 관리자 등록
   - 플라워샵 개설, 정보 수정, 상태 토글(활성 `active` / 비활성 `inactive`)
   - 플라워샵별 관리자 및 직원 목록 현황 통합 조회
2. **플라워샵 관리자/대표 (플라워샵당 2명 이상 등록 가능, 비밀번호 숫자 6자리)**
   - 소속 플라워샵 신규 직원 가입 승인(`pending` → `approved`) 및 퇴사 처리(`resigned`)
   - 직원별 급여 형태(시급 / 월급) 및 계산 단위(시간 / 분 단위) 설정 관리
   - 직원별 출퇴근 기록 직접 보완 및 월별 급여 정산 관리
   - 월별 직원 근무 현황 및 급여 데이터 UTF-8 with BOM CSV 다운로드
   - 본인 정보 수정 및 소속 플라워샵의 추가 관리자 등록 관리(별도 관리 페이지 모달/링크 방식)
3. **플라워샵 직원 (비밀번호 숫자 4자리)**
   - 등록된 활성 플라워샵 대상 가입 신청(동일 이름이라도 선택한 플라워샵 기준 식별, 최초 관리자가 존재하는 플라워샵만 가능)
   - 승인 후 선택한 플라워샵 스코프에서 로그인하여 본인 일별 출근/퇴근 시각 등록 및 수정
   - 월별 근무 기록 및 급여 산정 내역 조회, 본인 비밀번호 변경

### 안전한 서버 중심 DB 아키텍처 (Neon PostgreSQL)
- 모든 데이터 읽기/쓰기는 **Next.js Server Actions** 내부에서 Neon PostgreSQL 커넥션 풀을 통해 전용 실행되며, 브라우저에 `DATABASE_URL` 등 DB 자격 증명이 절대 노출되지 않습니다.
- 사용자 세션은 서명된 HttpOnly 쿠키(`APP_SESSION_SECRET`)로 안전하게 발급 및 검증됩니다.

## 2. 사용자와 사용 시나리오

### 사용자 역할 및 인증 체계

| 역할 | 인증 방식 | 비밀번호 자릿수 | 주요 허용 작업 |
| --- | --- | --- | --- |
| 시스템 관리자 | 이름 + 비밀번호 | **숫자 6자리** | 시스템 관리자 최초/추가 등록, 플라워샵 등록·수정·비활성화, 플라워샵별 관리자/직원 목록 조회 |
| 플라워샵 관리자 | 플라워샵 선택 + 이름 + 비밀번호 | **숫자 6자리** | 신규 직원 승인/퇴사 처리, 급여 형태(시급/월급) 및 계산기준(분/시간) 설정, 근무 기록 보완, 월별 정산 및 CSV 다운로드, 추가 관리자 등록, 본인 정보 수정 |
| 플라워샵 직원 | 플라워샵 선택 + 이름 + 비밀번호 | **숫자 4자리** | 가입 신청(신청 대기), 승인 후 출퇴근 기록 등록/수정, 월별 근무 현황 및 급여 산정액 조회, 본인 비밀번호 변경 |

### 상태값 정의 (Enum)
1. **플라워샵 상태 (`shops.status`)**
   - `active` (등록/활성): 정상 운영 상태. 플라워샵 관리자 및 직원의 로그인 및 가입 신청 가능
   - `inactive` (비활성): 시스템 관리자를 제외한 해당 플라워샵 소속 관리자 및 직원의 로그인 및 모든 접근이 즉시 차단됨
2. **직원 상태 (`staff.status`)**
   - `pending` (가입신청): 직원이 가입을 신청한 초기 상태(화면 표시: '승인대기'). 로그인 불가
   - `approved` (승인): 플라워샵 관리자가 승인한 상태. 정상 로그인 및 출퇴근 기능 이용 가능
   - `resigned` (퇴사): 플라워샵 관리자가 퇴사 처리한 상태. 로그인 및 신규 기록 차단, 과거 정산 데이터는 보존
3. **급여 형태 (`pay_type`) 및 계산 기준 (`time_unit`)**
   - `hourly` (시급): 일별 출퇴근 시간에 대해 시급 적용. 계산 기준은 `minute`(분 단위 정밀 정산) 또는 `hour`(시간 단위 절사 정산)
   - `monthly` (월급): 고정 월급여 적용 (월 중간 시작 시 해당 월 유효 일수 기준 일할 계산)

## 3. 기능 명세

### 핵심 기능 명세 및 수용 기준

| ID | 기능 | 동작 규칙 | 수용 기준 (Given/When/Then) |
| --- | --- | --- | --- |
| F-01 | 시스템 관리자 등록 및 추가 | DB에 시스템 관리자가 0명이면 `/system/setup`으로 자동 유도하여 최초 관리자를 등록합니다. 등록 후 세션이 부여되며, `/system/dashboard`에서 추가 시스템 관리자를 6자리 숫자 비밀번호로 등록할 수 있습니다. | **Given** 시스템 관리자가 0명이다. **When** `/system/setup`에서 이름과 6자리 숫자 비밀번호를 제출한다. **Then** `system_admins`에 등록되고 관리자 세션이 발급된다. |
| F-02 | 플라워샵 개설 및 상태 토글 | 시스템 관리자만 플라워샵을 신규 개설하거나 이름을 수정할 수 있고, 상태를 `active` ↔ `inactive`로 토글할 수 있습니다. | **Given** 시스템 관리자 세션이 있다. **When** 플라워샵 상태를 `inactive`로 변경한다. **Then** 해당 플라워샵 소속 사용자의 로그인 및 세션 요청이 즉시 거부된다. |
| F-03 | 플라워샵 관리자 및 추가 관리자 등록 | 플라워샵 개설 후 최초 관리자는 `/signup`에서 등록하고, 기존 관리자는 대시보드 하단 '추가 관리자 관리' 링크를 통해 `/shop-admin/admins` 페이지에서 동일 플라워샵의 추가 관리자를 6자리 비밀번호로 등록합니다. | **Given** 플라워샵 관리자로 로그인되어 있다. **When** 대시보드 하단 링크를 통해 `/shop-admin/admins`에서 추가 관리자를 등록한다. **Then** 해당 플라워샵에 동일한 이름이 아닌 신규 관리자가 추가 생성된다. |
| F-04 | 플라워샵별 직원 가입 신청 | 직원은 가입할 플라워샵을 먼저 선택한 후 이름과 4자리 비밀번호를 등록합니다. 타 플라워샵에 동명이인이 존재하더라도 선택한 플라워샵 내에 동일 이름이 없으면 가입 신청이 성공합니다. | **Given** 활성화된 A 플라워샵에 '홍길동'이 존재한다. **When** 직원이 B 플라워샵을 선택하고 '홍길동'으로 가입 신청을 한다. **Then** B 플라워샵의 `pending` 직운으로 정상 가입된다. |
| F-05 | 직원 승인 및 퇴사 처리 | 플라워샵 관리자는 '승인대기' 직원을 확인하고 급여 형태(`hourly`/`monthly`), 계산 단위(`minute`/`hour`), 급여액(원), 적용 시작일을 입력하여 `approved`로 승인합니다. 퇴사 시 상태를 `resigned`로 변경합니다. | **Given** `pending` 상태의 직원이 존재한다. **When** 관리자가 급여 조건 입력 후 '승인'을 누른다. **Then** 직원 상태가 `approved`로 갱신되고 로그인 권한이 부여된다. |
| F-06 | 플라워샵 스코프 로그인 | 로그인 시 반드시 [플라워샵 선택 + 사용자 구분 + 이름 + 비밀번호]를 제출합니다. 선택한 플라워샵 내부의 `shop_id`와 이름을 조합하여 검증하므로 서로 다른 플라워샵의 동일 이름 직원이 정확히 구분 로그인됩니다. | **Given** A/B 플라워샵에 모두 '김철수' 직원이 존재한다. **When** 로그인 화면에서 'B 플라워샵'을 선택하고 '김철수'로 로그인한다. **Then** B 플라워샵의 김철수 계정으로 대시보드가 열린다. |
| F-07 | 시급 직원의 일별 출퇴근 기록 | 승인된 시급 직원은 날짜(기본 오늘), 출근 시각, 퇴근 시각을 등록 및 수정합니다. 모바일 화면에서 터치하기 쉬운 빅사이즈 타임피커 UI가 제공됩니다. | **Given** 승인된 시급 직원 세션이 있다. **When** 유효한 날짜와 출퇴근 시간을 제출한다. **Then** `attendance`에 저장되고 총 근무 분이 즉시 화면에 반영된다. |
| F-08 | 관리자의 근무 기록 보완 및 모바일 정산 | 플라워샵 관리자는 직원의 출퇴근 기록을 직접 수정 및 추가할 수 있으며, 모바일(S25, 아이폰16) 환경에서도 깨짐 없이 수평 스크롤/카드로 직원별 근무 및 월 급여 정산 데이터를 조회합니다. | **Given** 모바일 브라우저(폭 360~430px)로 접근한다. **When** 급여 정산 화면을 확인한다. **Then** 레이아웃 깨짐이나 이탈 없이 수평 스크롤 표 또는 카드 목록으로 깨끗하게 출력된다. |
| F-09 | 월별 정산 내역 CSV 다운로드 | 플라워샵 관리자는 선택한 월(`YYYY-MM`)의 전체 소속 직원 근무 시간과 급여 산정 결과를 UTF-8 with BOM 형식의 CSV 파일로 다운로드합니다. | **Given** 관리자가 특정 연월을 선택했다. **When** 'CSV 다운로드' 버튼을 클릭한다. **Then** `flower_payroll_YYYY_MM.csv` 파일이 정상 다운로드된다. |
| F-10 | 본인 정보 및 비밀번호 변경 | 모든 사용자(시스템 관리자 6자리, 플라워샵 관리자 6자리, 직원 4자리)는 각각 로그인 후 본인의 이름과 비밀번호를 안전하게 수정할 수 있습니다. | **Given** 로그인된 사용자이다. **When** 기존 비밀번호 확인 후 자릿수 규칙에 맞는 새 비밀번호를 제출한다. **Then** bcrypt 해시값이 안전하게 갱신된다. |

## 4. 화면과 주소(URL) 구성

### 전체 화면 흐름도
`메인 화면 (/)` → `통합 로그인 (/login)` 또는 `가입 신청 (/signup)` → 권한별 대시보드 (`/system/dashboard`, `/shop-admin/dashboard`, `/employee/dashboard`) 및 `/shop-admin/admins` (추가 관리자 전용 관리 페이지)

### URL별 화면 상세 구성 및 모바일 반응형 설계

| URL | 화면 구성 및 모바일(S25/아이폰16) 반응형 UX |
| --- | --- |
| `/` (메인) | • 상단 고정 헤더 배너: **'플라워샵 근무 관리'** (따뜻한 Hand-crafted 펠트 아트 그래픽 테마 적용)<br>• 중앙 영역: 모바일 반응형 카드 (`px-4 max-w-md mx-auto`) - 프로그램 소개 카드 및 **'로그인'**, **'가입 신청'** 버튼<br>• 하단 영역: 시스템 관리자 전용 텍스트 링크 ('시스템 관리자 접속') |

## 5. 데이터 모델

### 데이터베이스 스키마 (Neon PostgreSQL 전용 실행 DDL)

Neon PostgreSQL 환경에서 앱 실행 전 반드시 아래 DDL 스크립트를 Neon SQL Editor에서 실행하거나 `schema.sql` 파일을 통해 초기화해야 합니다.

```sql
-- 1. 기존 테이블 정리
DROP TABLE IF EXISTS auth_attempts CASCADE;
DROP TABLE IF EXISTS attendance CASCADE;
DROP TABLE IF EXISTS compensation CASCADE;
DROP TABLE IF EXISTS staff CASCADE;
DROP TABLE IF EXISTS shop_admins CASCADE;
DROP TABLE IF EXISTS shops CASCADE;
DROP TABLE IF EXISTS system_admins CASCADE;

-- 2. 시스템 관리자 테이블 (복수 등록 지원, 6자리 비밀번호)
CREATE TABLE system_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  pin_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. 플라워샵 테이블 (상태: active, inactive)
CREATE TABLE shops (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 4. 플라워샵 관리자 테이블 (플라워샵별 복수 등록 지원, 6자리 비밀번호)
CREATE TABLE shop_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (shop_id, name)
);

-- 5. 플라워샵 직원 테이블 (상태: pending, approved, resigned, 4자리 비밀번호)
CREATE TABLE staff (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_hash TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'approved', 'resigned')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  resigned_at TIMESTAMPTZ,
  UNIQUE (shop_id, name)
);

-- 6. 직원 급여 조건 테이블 (시급/월급, 시간/분 단위 정산)
CREATE TABLE compensation (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  pay_type TEXT NOT NULL CHECK (pay_type IN ('hourly', 'monthly')),
  time_unit TEXT NOT NULL DEFAULT 'minute' CHECK (time_unit IN ('minute', 'hour')),
  amount_krw INTEGER NOT NULL CHECK (amount_krw > 0),
  effective_from DATE NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (staff_id, effective_from)
);

-- 7. 출퇴근 근무 기록 테이블 (시급 직원용 일별 기록)
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  work_date DATE NOT NULL,
  clock_in TIME NOT NULL,
  clock_out TIME NOT NULL,
  total_minutes INTEGER NOT NULL CHECK (total_minutes > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (staff_id, work_date),
  CHECK (clock_out > clock_in)
);

-- 8. 무차별 대입 공격 방지 테이블
CREATE TABLE auth_attempts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  identity_hash TEXT NOT NULL,
  attempted_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  succeeded BOOLEAN NOT NULL DEFAULT FALSE
);

-- 9. 성능 최적화 인덱스
CREATE INDEX idx_shops_status ON shops(status);
CREATE INDEX idx_shop_admins_shop_id ON shop_admins(shop_id);
CREATE INDEX idx_staff_shop_status ON staff(shop_id, status);
CREATE INDEX idx_compensation_staff ON compensation(staff_id, effective_from DESC);
CREATE INDEX idx_attendance_staff_date ON attendance(staff_id, work_date);
CREATE INDEX idx_auth_attempts_identity ON auth_attempts(identity_hash, attempted_at DESC);
```

## 8. 품질 기준 (성능·보안·접근성)

### 계산 규칙 및 보안 무결성
1. **비밀번호 규칙**
   - 시스템 관리자 & 플라워샵 관리자: 반드시 **숫자 6자리** (`^[0-9]{6}$`)
   - 플라워샵 직원: 반드시 **숫자 4자리** (`^[0-9]{4}$`)
   - 모든 비밀번호는 단방향 bcrypt 해시 형태로만 DB에 저장되며 평문 저장 절대 금지
2. **플라워샵 비활성화 시 보안 통제**
   - `shops.status = 'inactive'`일 경우, 해당 플라워샵의 모든 관리자와 직원은 로그인 시도가 즉시 거부되며 기존 발급된 세션 쿠키도 요청 즉시 무효화됩니다.
3. **급여 계산 알고리즘**
   - **시급(`hourly`)**:
     - `time_unit = 'minute'`: `(총 근무 분 / 60) * 시급`, 원 단위 반올림 (`Math.round`)
     - `time_unit = 'hour'`: `Math.floor(총 근무 분 / 60) * 시급` (시간 단위 절사 정산)
   - **월급(`monthly`)**:
     - 기본적으로 해당 월 고정액 지급. 월 중간 시작일 적용 시 해당 월 전체 일수 대비 유효 일수로 일할 계산
4. **CSV 데이터 다운로드 형식**
   - 파일명: `flower_payroll_[YYYY_MM].csv`
   - UTF-8 with BOM 인코딩 (엑셀에서 한글 깨짐 방지)
   - 헤더: `직원명,상태,급여형태,계산단위,적용금액(원),해당월 총 근무시간(분),지급예정액(원)`

## 9. 배포와 운영

### 배포 및 Neon DB 스키마 생성 절차

1. **Neon DB Console 접속**: Neon 콘솔(console.neon.tech)에 접속하여 사용 중인 DB 프로젝트의 **SQL Editor**로 이동합니다.
2. **DDL 스키마 적용**: `data` 섹션에 작성된 전체 SQL(테이블 8개 및 성능 최적화 인덱스)을 복사하여 SQL Editor에서 실행(`Run`)합니다.
3. **Vercel 환경 변수 설정**: Vercel 대시보드의 Environment Variables 메뉴에서 `DATABASE_URL`(Neon Pooled Connection String)과 `APP_SESSION_SECRET`을 확인 및 등록합니다.
4. **Vercel 재배포**: Vercel 대시보드에서 `Redeploy`를 실행하여 생성된 Neon DB와 Next.js Server Actions 연동을 마무리합니다.

## 10. 테스트 계획

### 테스트 계획 및 시나리오

1. **Smoke 검증 (공개 경로 HTTP 200)**
   - `GET /`: 메인 화면 정상 로드, 상단 고정 배너 및 시스템 관리자 링크 렌더링 확인
   - `GET /login`: 플라워샵 드롭다운, 관리자/직원 탭 정상 렌더링 확인
   - `GET /signup`: 직원 가입 신청 및 최초 관리자 개설 탭 렌더링 확인
   - `GET /system/login`: 시스템 관리자 로그인 카드 렌더링 확인
   - `GET /system/setup`: 시스템 관리자 0명일 때 최초 등록 폼 렌더링 확인

2. **플라워샵별 동일 이름 중복 가입 및 로그인 스코프 검증**
   - **Given** A 플라워샵과 B 플라워샵이 활성화되어 있다.
   - **When** A 플라워샵에 '이영희', B 플라워샵에 '이영희' 이름으로 각각 가입을 신청하고 승인받는다.
   - **Then** DB 제약조건 오류 없이 두 계정이 모두 정상 저장되며, 로그인 화면에서 B 플라워샵을 선택하여 로그인 시 B 플라워샵 이영희 대시보드로 정확히 접속된다.

3. **모바일(S25/아이폰16) 반응형 UI 레이아웃 검증**
   - **Given** 브라우저 너비를 360px 및 393px로 설정한다.
   - **When** 관리자 급여 정산 페이지 및 직원 출퇴근 입력 페이지를 로딩한다.
   - **Then** 좌우 짤림 현상 없이 수평 스크롤 혹은 카드 형태 컴포넌트로 정상 표시된다.

4. **추가 관리자 분리 링크 이동 검증**
   - **Given** 플라워샵 관리자로 로그인되어 대시보드에 접속해 있다.
   - **When** 대시보드 하단의 '추가 관리자 등록/관리 →' 링크를 클릭한다.
   - **Then** `/shop-admin/admins` 페이지로 이동하여 추가 관리자를 성공적으로 등록 및 목록 조회를 수행할 수 있다.
