## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
'플라워샵 근무 관리'는 복수의 플라워샵(매장) 환경에서 3계층 권한(시스템 관리자, 플라워샵 대표, 플라워샵 직원)을 기반으로 출퇴근 기록, 시급 관리, 월별 급여를 자동 집계하는 멀티 테넌트 웹 애플리케이션입니다.

### 핵심 가치 및 동작 원칙
1. **3계층 권한 모델**:
   - **시스템 관리자 (System Admin)**: 전체 플라워샵을 등록, 수정, 조회할 수 있는 마스터 권한.
   - **플라워샵 대표 (Shop Owner)**: 해당 플라워샵에 소속된 전체 직원의 내역(직원 등록 승인/퇴사, 근무 시간, 시급 설정, 월별 근무 및 급여)을 조회하고 수정할 수 있는 매장 관리자 권한.
   - **플라워샵 직원 (Shop Staff)**: 소속 플라워샵에서 일별 출근/퇴근 시간을 직접 등록하고, 본인의 월별 근무 현황과 예상 급여 산정 내역을 조회하는 직원 권한.
2. **시스템 관리자 최초 등록 분기**:
   - 시스템에 등록된 시스템 관리자가 전혀 없을 경우, 메인 접속 시 자동으로 `/system-setup` 화면으로 이동하여 마스터 계정 생성을 강제합니다.
3. **플라워샵 등록 통제**:
   - 플라워샵 등록 및 수정은 시스템 관리자 로그인(이름 + 4자리 PIN)을 거친 후에만 가능합니다.
4. **플라워샵별 관리자 등록 버그 원천 해결**:
   - 신규 샵에 관리자가 없는데 "이미 관리자가 존재합니다" 오류가 발생하는 문제를 해결하기 위해, DB 쿼리에서 반드시 현재 선택된 `shop_id`를 기준으로 `WHERE shop_id = :shopId AND is_admin = true` 조건을 엄격히 스코핑합니다.
5. **보안 및 입력 검증**:
   - 모든 비밀번호(4자리 PIN) 등록 및 수정 시 '비밀번호 확인' 필드를 통한 더블 체크 검증을 거칩니다.

## 2. 사용자와 사용 시나리오

### 사용자 역할과 권한 매트릭스

| 역할 | 인증 방식 | 주요 접근 가능 화면 | 부여 권한 및 책임 |
| --- | --- | --- | --- |
| **시스템 관리자** | 이름 + 4자리 PIN | `/system-setup`, `/shop/register`, `/` | - 시스템 내 모든 플라워샵 등록/수정/조회<br>- 전체 시스템 상태 모니터링 |
| **플라워샵 대표** | 샵 선택 + 이름 + 4자리 PIN | `/admin/setup`, `/admin`, `/admin/attendance` | - 특정 샵의 관리자 등록/정보 수정<br>- 소속 직원의 가입 승인(`pending` → `active`), 퇴사 처리(`resigned`)<br>- 직원별 시급 설정 및 수정<br>- 소속 직원 전체의 일별 출퇴근 기록 수정 및 월별 급여 집계 조회 |
| **플라워샵 직원** | 샵 선택 + 이름 + 4자리 PIN | `/employee/dashboard` | - 본인의 일별 출근/퇴근 시간 실시간 등록 및 당일 기록 확인<br>- 본인의 월별 총 근무 시간 및 예상 급여 산정 내역 조회<br>- 본인 4자리 PIN 비밀번호 변경 |

### 사용자 시나리오 흐름
1. **시스템 초기 실행**: DB에 시스템 관리자가 0명이면 자동으로 `/system-setup`으로 유도되어 최초 시스템 관리자를 생성합니다.
2. **플라워샵 개설**: 시스템 관리자가 인증 후 `/shop/register`에서 신규 플라워샵을 등록합니다.
3. **플라워샵 대표 등록**: 메인 화면(`/`)에서 플라워샵을 검색/선택하여 허브(`/shop/[id]`)로 이동합니다. 해당 샵에 대표가 없으면 '관리자 등록' 버튼만 노출되며, `/admin/setup`에서 해당 샵 전용 대표를 등록합니다.
4. **직원 가입 및 승인**: 대표가 등록된 플라워샵 허브에서는 '직원 가입'과 '직원 로그인'이 노출됩니다. 직원이 가입 신청하면 대표 대시보드(`/admin`)에서 시급을 확정하고 승인(`active`)합니다.
5. **출퇴근 및 급여 정산**: 재직 중인 직원은 매일 대시보드에서 출근/퇴근을 누르고, 대표는 월별 총 근무 시간과 급여를 집계하여 확인 및 보완합니다.

## 3. 기능 명세

### 기능 상세 명세

| 기능 ID | 기능명 | 설명 | 담당 권한 | 수용 기준 (Given/When/Then) |
| --- | --- | --- | --- | --- |
| F-01 | 시스템 관리자 최초 등록 | 시스템 내 관리자 0명일 때 초기 관리자 계정 생성 | 비회원(최초) | **Given** 시스템에 시스템 관리자가 없다.<br>**When** 사용자가 접속한다.<br>**Then** `/system-setup`으로 자동 리다이렉트되며, 4자리 PIN을 2회 입력받아 일치할 때만 시스템 관리자가 생성된다. |
| F-02 | 시스템 관리자 인증 플라워샵 관리 | 시스템 관리자만 플라워샵을 신규 등록하거나 기존 매장명을 수정 가능 | 시스템 관리자 | **Given** 시스템 관리자로 인증(PIN 입력)되었다.<br>**When** `/shop/register`에서 플라워샵명을 입력하고 저장한다.<br>**Then** `shops` 테이블에 반영되고 메인 화면 목록에 즉시 노출된다. |
| F-03 | 메인 플라워샵 검색 및 허브 분기 | 등록된 플라워샵을 검색어로 필터링하여 선택하고 허브 화면으로 이동 | 전체 | **Given** 메인 화면(`/`)에 접속했다.<br>**When** 검색창에 샵 이름을 입력한다.<br>**Then** 실시간으로 필터링된 플라워샵 카드 목록이 표시되며 클릭 시 `/shop/[id]`로 이동한다. |
| F-04 | 플라워샵별 관리자 독립 등록/수정 (버그 해결) | 타 매장 관리자 존재 여부와 무관하게, 현재 `shop_id`의 대표 유무만 정확히 판별하여 등록/수정 수행 | 플라워샵 대표 | **Given** 신규 플라워샵에 대표가 등록되어 있지 않다.<br>**When** `/admin/setup?shop_id=[id]`에 진입한다.<br>**Then** "이미 관리자가 존재합니다" 오류 없이 빈 폼(등록 모드)이 열리며 정상 등록된다. 이미 있는 경우 기존 대표 정보가 표시되며 수정 모드로 동작한다. |
| F-05 | 직원 회원가입 및 PIN 확인 | 직원이 특정 플라워샵에 소속 신청 (PIN 2회 입력 검증) | 플라워샵 직원 | **Given** `/shop/[id]` 허브에서 '직원 가입'을 눌렀다.<br>**When** 이름과 4자리 PIN(비밀번호, 비밀번호 확인)을 동일하게 입력 후 신청한다.<br>**Then** `staff` 테이블에 `status='pending'`, `is_admin=false`로 등록된다. |
| F-06 | 대표의 직원 관리 및 급여/시급 통제 | 대표가 대기 직원을 승인(`active`), 시급 지정, 퇴사 처리(`resigned`) | 플라워샵 대표 | **Given** 대표가 `/admin`에 로그인했다.<br>**When** 직원의 시급을 설정하고 승인 또는 퇴사 버튼을 누른다.<br>**Then** 상태가 갱신되며, `active` 상태인 직원만 출퇴근 기록이 가능해진다. |
| F-07 | 직원 출퇴근 기록 및 본인 내역 조회 | 승인된 직원이 당일 출근/퇴근을 등록하고 본인의 월별 근무시간 및 급여 조회 | 플라워샵 직원 | **Given** 직원이 `/employee/dashboard`에 로그인했다.<br>**When** '출근하기' 또는 '퇴근하기' 버튼을 누른다.<br>**Then** 당일 날짜와 시간이 초 단위 제외(HH:mm) 기록되며, 이번 달 총 근무 시간 및 (근무시간 × 시급) 예상 급여가 실시간 계산된다. |
| F-08 | 대표의 전사 근무 시간 및 급여 보완 | 대표가 직원들의 누락된 출퇴근 시간을 수정하거나 월별 정산 내역 조회 | 플라워샵 대표 | **Given** 대표가 `/admin/attendance`에 접근했다.<br>**When** 특정 직원의 출근/퇴근 시간을 직접 보완하거나 월별 필터를 변경한다.<br>**Then** 수정된 시간을 바탕으로 급여 합계가 재산출된다. |

## 5. 데이터 모델

### 데이터베이스 스키마 및 RLS 보안 정책 (Supabase PostgreSQL)

#### 1. 테이블 정의 스키마

```sql
-- 1. 시스템 마스터 관리자 (시스템 전체 관리)
CREATE TABLE system_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  pin_code TEXT NOT NULL, -- 4자리 숫자 PIN
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 2. 플라워샵 매장
CREATE TABLE shops (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 3. 플라워샵 구성원 (대표 및 직원 통합 관리)
CREATE TABLE staff (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_code TEXT NOT NULL, -- 4자리 숫자 PIN
  hourly_wage INTEGER NOT NULL DEFAULT 10000, -- 원 단위 기본 시급
  is_admin BOOLEAN NOT NULL DEFAULT false, -- true: 플라워샵 대표, false: 일반 직원
  status TEXT NOT NULL DEFAULT 'pending', -- 'pending'(승인대기), 'active'(재직), 'resigned'(퇴사)
  created_at TIMESTAMPTZ DEFAULT now(),
  CONSTRAINT uq_shop_staff UNIQUE (shop_id, name)
);

-- 4. 일별 출퇴근 기록
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  work_date DATE NOT NULL DEFAULT CURRENT_DATE,
  clock_in TIME NOT NULL,
  clock_out TIME,
  total_minutes INTEGER DEFAULT 0, -- 퇴근 시 (clock_out - clock_in) 계산된 분 단위 근무시간
  created_at TIMESTAMPTZ DEFAULT now(),
  CONSTRAINT uq_staff_work_date UNIQUE (staff_id, work_date)
);
```

#### 2. 플라워샵 대표 등록 버그 원천 해결 쿼리
- **버그 원인**: 기존 로직에서 매장 조건 없이 전체 테이블에서 `is_admin = true`를 검색하여 타 플라워샵의 관리자가 있으면 신규 매장인데도 관리자가 이미 존재한다고 오판단함.
- **해결 쿼리 (특정 shop_id 한정 스코핑)**:
```sql
-- 반드시 URL 파라미터 또는 선택된 shop_id를 WHERE 절에 명시
SELECT id, name, is_admin, hourly_wage, status 
FROM staff 
WHERE shop_id = :targetShopId AND is_admin = true 
LIMIT 1;
```
- 결과가 0건이면 무조건 **대표 등록 모드**, 1건 이상이면 기존 대표 정보 수정 모드로 동작.

#### 3. Row Level Security (RLS) 정책 사양
- 멀티 테넌트 데이터 보호를 위해 모든 테이블에 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` 적용.
- `system_admins`: 인증 확인용 API(Server Actions/Route Handler)를 통해 Service Role로 안전하게 조회 및 등록.
- `shops`: 메인 화면 조회를 위해 익명/공개 읽기(`SELECT`) 허용. 생성/수정은 시스템 관리자 세션 검증 후 허용.
- `staff`: 동일한 `shop_id`를 가진 사용자 간 본인 소속 매장 확인 허용. 타 매장 데이터 노출 방지.
- `attendance`: 직원은 본인의 `staff_id` 데이터만 조회/등록 가능, 플라워샵 대표는 본인 매장(`shop_id`) 소속 직원의 모든 근태 데이터 조회/수정 가능.

## 8. 품질 기준 (성능·보안·접근성)

### 품질 및 보안 검증 기준
1. **4자리 PIN 보안 및 정규식**:
   - 시스템 관리자, 대표, 직원의 모든 PIN 번호는 정확히 4자리 숫자(`^[0-9]{4}$`)여야 합니다.
   - 신규 등록 및 변경 시 '비밀번호 확인' 필드를 필수로 입력받아 100% 일치해야 저장 버튼이 활성화됩니다.
2. **멀티 테넌트 격리성**:
   - 모든 매장 데이터(`staff`, `attendance`)는 URL 파라미터의 `shop_id`와 인증된 세션의 `shop_id`를 교차 검증하여 타 매장 침범을 완전히 방지합니다.
3. **정확한 근무 시간 및 급여 산출 공식**:
   - 출근 기록 후 퇴근 전까지는 '근무 중' 상태로 표시되며 정산 집계에 포함되지 않습니다.
   - 일별 근무 분 = `퇴근 시간(분) - 출근 시간(분)` (휴게 시간 차감 없음).
   - 월 총 급여 산출: `Math.round((월 누적 근무 분 / 60) * staff.hourly_wage)` (원 단위 반올림 처리).

## 10. 테스트 계획

### 수용 테스트 시나리오 및 검증 항목

- **테스트 1: 시스템 관리자 최초 등록 강제 리다이렉트**
  - **Given**: `system_admins` 테이블에 등록된 레코드가 0건이다.
  - **When**: 사용자가 사이트 루트(`/`)에 접속한다.
  - **Then**: 즉시 `/system-setup` 화면으로 자동 이동하며, PIN 일치 검증을 통과해야 첫 시스템 관리자가 생성되고 메인 화면으로 이동한다.

- **테스트 2: 플라워샵 대표 등록 버그 해결 (매장 격리 검증)**
  - **Given**: 플라워샵 A에는 이미 대표 관리자가 등록되어 있고, 새로 생성한 플라워샵 B에는 대표가 없다.
  - **When**: 사용자가 플라워샵 B의 허브(`/shop/B`)에서 [대표 관리자 등록]을 눌러 `/admin/setup?shop_id=B`에 진입한다.
  - **Then**: "이미 해당 플라워샵에 관리자가 존재합니다" 오류가 뜨지 않고, 정상적인 빈 등록 폼이 노출되어 대표 계정을 생성할 수 있다.

- **테스트 3: 직원 가입 신청 및 대표 승인 워크플로우**
  - **Given**: 직원이 `/signup?shop_id=A`에서 이름과 4자리 PIN을 입력하여 가입을 신청했다.
  - **When**: 해당 직원이 바로 출근 화면 로그인을 시도한다.
  - **Then**: `status`가 `pending`이므로 "대표의 승인이 필요한 계정입니다" 경고가 발생하며 진입이 차단된다.
  - **When**: 플라워샵 대표가 `/admin`에서 해당 직원의 시급을 11,000원으로 설정하고 [승인] 버튼을 누른다.
  - **Then**: 직원의 상태가 `active`로 변경되고, 즉시 출근 등록이 가능해진다.

- **테스트 4: 출퇴근 기록 및 월급 계산 정합성**
  - **Given**: 승인된 직원이 09:00에 출근하고 18:00에 퇴근을 기록했다 (총 9시간 = 540분, 시급 11,000원).
  - **When**: 직원 마이페이지(`/employee/dashboard`)와 대표 관리자 정산 화면(`/admin/attendance`)을 조회한다.
  - **Then**: 양쪽 모두에서 해당 일자의 근무시간 9시간 00분과 예상 급여 99,000원이 정확히 일치하여 표시된다.
