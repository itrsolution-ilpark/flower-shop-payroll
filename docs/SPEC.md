## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
'플라워샵 근무 관리'는 복수의 플라워샵(매장) 환경에서 3계층 권한(시스템 관리자, 플라워샵 관리자, 플라워샵 직원)을 기반으로 출퇴근 기록, 시급 관리, 월별 급여를 자동 집계하는 세련된 멀티 테넌트 웹 애플리케이션입니다.

### 핵심 가치 및 동작 원칙
1. **3계층 권한 체계**:
   - **시스템 관리자 (System Admin)**: 전체 플라워샵을 등록, 수정, 조회할 수 있는 시스템 마스터 권한.
   - **플라워샵 관리자 (Shop Admin)**: 해당 플라워샵에 소속된 전체 직원의 내역(직원 승인/퇴사 상태 관리, 근무 시간, 시급 설정, 월별 근무 및 급여)을 조회하고 수정할 수 있는 매장 관리 권한.
   - **플라워샵 직원 (Shop Staff)**: 소속 플라워샵에서 날짜와 출퇴근 시간을 선택하여 등록/수정하고, 본인의 월별 근무 현황과 급여 산정 내역을 조회하는 직원 권한.
2. **시스템 관리자 최초 등록 분기**:
   - 시스템에 등록된 시스템 관리자가 없을 경우, 접속 시 자동으로 `/system-setup` 화면으로 유도되어 마스터 계정 생성을 완료합니다.
3. **플라워샵 등록 통제**:
   - 플라워샵 등록 및 수정은 시스템 관리자 인증(이름 + 4자리 PIN)을 거친 후에만 가능합니다.
4. **플라워샵별 관리자 독립 등록 (오류 원천 해결)**:
   - 특정 플라워샵의 관리자 등록 화면 진입 시, 반드시 현재 선택된 `shop_id`를 기준으로 관리자 존재 여부를 판별하여 타 매장 데이터 간섭 없이 등록/수정됩니다.
5. **재직자 중심 로그인 및 유연한 근태 입력**:
   - 직원 로그인 목록에는 퇴사자(`resigned`)를 배제하고 승인 완료된 재직자(`active`)만 노출합니다.
   - 직원은 당일 자동 기록뿐만 아니라 날짜와 출근/퇴근 시간을 직접 선택하여 세련된 휠/타임피커로 유연하게 등록 및 수정할 수 있습니다.

## 2. 사용자와 사용 시나리오

### 사용자 역할과 권한 매트릭스

| 역할 | 인증 방식 | 주요 접근 가능 화면 | 부여 권한 및 책임 |
| --- | --- | --- | --- |
| **시스템 관리자** | 이름 + 4자리 PIN | `/system-setup`, `/shop/register`, `/` | - 시스템 내 모든 플라워샵 등록/수정/조회<br>- 전체 시스템 상태 모니터링 |
| **플라워샵 관리자** | 샵 선택 + 이름 + 4자리 PIN | `/admin/setup`, `/admin`, `/admin/attendance` | - 특정 샵의 관리자 등록/정보 수정<br>- 소속 직원의 가입 승인(`pending` → `active`), 퇴사 처리(`resigned`)<br>- 직원별 시급 설정 및 수정<br>- 소속 직원 전체의 승인/재직/퇴사 상태 확인 및 근무/급여 정산 내역 보완 |
| **플라워샵 직원** | 샵 선택(목록에서 본인 선택) + 4자리 PIN | `/employee/dashboard` | - 퇴사자를 제외한 재직자 로그인<br>- 날짜 선택 및 세련된 시간 피커를 통한 출근/퇴근 시간 등록 및 수정<br>- 본인의 월별 총 근무 시간 및 예상 급여 산정 내역 조회<br>- 본인 4자리 PIN 비밀번호 변경 |

### 사용자 시나리오 흐름
1. **시스템 초기 실행**: DB에 시스템 관리자가 없으면 자동으로 `/system-setup`으로 유도되어 최초 시스템 관리자를 생성합니다.
2. **플라워샵 등록**: 시스템 관리자가 인증 후 `/shop/register`에서 신규 플라워샵을 등록합니다.
3. **플라워샵 관리자 등록**: 전체 플라워샵 메인(`/`)에서 매장을 검색/선택하여 개별 플라워샵 메인(`/shop/[id]`)으로 이동합니다. 관리자가 없으면 '관리자 등록' 버튼만 노출되며, `/admin/setup`에서 해당 샵 관리자를 등록합니다.
4. **직원 가입 및 승인**: 관리자가 등록된 플라워샵 메인에서는 '직원 가입 신청'과 '직원 로그인'이 노출됩니다. 직원이 가입 신청하면 관리 대시보드(`/admin`)에서 시급을 책정하고 승인합니다.
5. **출퇴근 등록 및 월별 정산**: 재직 중인 직원은 캘린더 날짜와 시간 선택 UI를 통해 근무 기록을 등록하고, 관리자는 근무 기록/급여 정산 화면에서 직원별 상태(승인대기, 재직, 퇴사)와 합산 급여를 확인 및 보완합니다.

## 3. 기능 명세

### 기능 상세 명세

| 기능 ID | 기능명 | 설명 | 담당 권한 | 수용 기준 (Given/When/Then) |
| --- | --- | --- | --- | --- |
| F-01 | 시스템 관리자 최초 등록 | 시스템 내 관리자 0명일 때 초기 마스터 계정 생성 | 비회원(최초) | **Given** 시스템에 시스템 관리자가 없다.<br>**When** 사용자가 접속한다.<br>**Then** `/system-setup`으로 자동 이동하며, 4자리 PIN 2회 일치 시 마스터 계정이 생성된다. |
| F-02 | 시스템 관리자 플라워샵 관리 | 시스템 관리자 인증 후 플라워샵 신규 등록 및 수정 | 시스템 관리자 | **Given** 시스템 관리자 PIN 인증을 완료했다.<br>**When** `/shop/register`에서 플라워샵 이름을 입력하고 저장한다.<br>**Then** 매장이 생성되고 메인 화면 검색 목록에 반영된다. |
| F-03 | 플라워샵 검색 및 매인 이동 | 상단 검색창에 키워드를 입력해 플라워샵을 찾고 선택하여 해당 플라워샵 메인으로 이동 | 전체 | **Given** 전체 플라워샵 메인(`/`) 상단에 접속했다.<br>**When** 검색창에 매장명을 입력한다.<br>**Then** 실시간 필터링 목록이 즉시 표시되며 클릭 시 해당 플라워샵 메인(`/shop/[id]`)으로 이동한다. |
| F-04 | 플라워샵 관리자 등록 및 수정 | 타 매장 관리자와 격리하여 현재 `shop_id`의 관리자 존재 여부만 정확히 판별하여 등록/수정 | 플라워샵 관리자 | **Given** 해당 플라워샵에 관리자가 없다.<br>**When** `/admin/setup?shop_id=[id]`에 진입한다.<br>**Then** "이미 관리자가 존재합니다" 오류 없이 신규 등록 폼이 열리며 정상 저장된다. 이미 존재할 경우 기존 정보가 채워진 수정 모드로 동작한다. |
| F-05 | 재직 직원 로그인 및 퇴사자 배제 | 직원 로그인 시 퇴사 처리된 직원은 선택 목록에서 원천 배제 | 플라워샵 직원 | **Given** 플라워샵 메인(`/shop/[id]`)에서 직원 로그인을 선택했다.<br>**When** 직원 선택 드롭다운 목록을 확인한다.<br>**Then** `resigned`(퇴사) 상태의 직원은 목록에 나타나지 않으며 `active`(재직) 직원만 선택 가능하다. |
| F-06 | 캘린더 날짜 및 시간 피커 출퇴근 등록/수정 | 날짜를 자유롭게 선택하고 세련된 시/분 피커로 출근 및 퇴근 시간을 정밀 등록/수정 | 플라워샵 직원 | **Given** 직원이 대시보드에 로그인했다.<br>**When** 근무 날짜(기본값: 오늘)를 선택하고 출근 시간(예: 09:30), 퇴근 시간(예: 18:30)을 모달/피커로 입력 후 저장한다.<br>**Then** 해당 날짜의 근태 레코드가 저장/수정되고 분 단위 근무 시간과 예상 급여가 즉시 갱신된다. |
| F-07 | 근무 기록 및 급여 정산 상태 표시 | 직원별 승인대기, 재직, 퇴사 상태 뱃지와 함께 출퇴근 내역 및 총 급여 조회 | 플라워샵 관리자 | **Given** 관리자가 `/admin/attendance`에 접속했다.<br>**When** 월별 정산 화면을 확인한다.<br>**Then** 각 직원 이름 옆에 상태 뱃지(승인대기: 주황, 재직: 초록, 퇴사: 회색)가 표시되고 일자별 기록 수정 및 월 급여 합계가 표시된다. |
| F-08 | 직원 승인, 시급 책정 및 퇴사 전환 | 대기 직원의 시급 설정 및 승인, 재직 직원의 퇴사 처리 | 플라워샵 관리자 | **Given** 관리자가 `/admin`에 로그인했다.<br>**When** 승인대기 직원의 시급을 입력하고 승인 버튼을 누르거나, 재직 직원의 퇴사 처리 버튼을 누른다.<br>**Then** 직원의 `status`가 즉시 변경되어 권한 및 로그인 가시성이 제어된다. |

### 전체 화면 목록 및 레이아웃 상세

모든 화면은 상단부터 차례대로 정돈된 여백과 카드 UI로 배치되며, 버튼명 표기에는 대괄호(`[]`)를 사용하지 않고 직관적인 텍스트 레이블을 적용합니다.

| `/admin/setup` | 플라워샵별 관리자 등록 | 1. 상단 헤더: 플라워샵별 관리자 등록 화면 타이틀<br>2. 고정 안내: 소속 플라워샵명 고정 뱃지<br>3. 등록/수정 폼: 관리자 이름 인풋, 4자리 PIN 인풋, 4자리 PIN 확인 인풋<br>4. 액션 버튼: 관리자 정보 저장 완료 버튼 |

## 5. 데이터 모델

### 데이터베이스 스키마 및 RLS 보안 정책 (Supabase PostgreSQL)

#### 1. 테이블 정의 스키마

```sql
-- 1. 시스템 마스터 관리자 (시스템 전체 관리)
CREATE TABLE system_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL,
  pin_code TEXT NOT NULL, -- 4자리 숫자 PIN
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 2. 플라워샵 매장
CREATE TABLE shops (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  created_at TIMESTAMPTZ DEFAULT now()
);

-- 3. 플라워샵 구성원 (대표 및 직원 통합 관리)
CREATE TABLE staff (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_code TEXT NOT NULL, -- 4자리 숫자 PIN
  hourly_wage INTEGER NOT NULL DEFAULT 10000, -- 원 단위 기본 시급
  is_admin BOOLEAN NOT NULL DEFAULT false, -- true: 플라워샵 대표, false: 일반 직원
  status TEXT NOT NULL DEFAULT 'pending', -- 'pending'(승인대기), 'active'(재직), 'resigned'(퇴사)
  created_at TIMESTAMPTZ DEFAULT now(),
  CONSTRAINT uq_shop_staff UNIQUE (shop_id, name)
);

-- 4. 일별 출퇴근 기록
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  work_date DATE NOT NULL DEFAULT CURRENT_DATE,
  clock_in TIME NOT NULL,
  clock_out TIME,
  total_minutes INTEGER DEFAULT 0, -- 퇴근 시 (clock_out - clock_in) 계산된 분 단위 근무시간
  created_at TIMESTAMPTZ DEFAULT now(),
  CONSTRAINT uq_staff_work_date UNIQUE (staff_id, work_date)
);
```

#### 2. 플라워샵 대표 등록 버그 원천 해결 쿼리
- **버그 원인**: 기존 로직에서 매장 조건 없이 전체 테이블에서 `is_admin = true`를 검색하여 타 플라워샵의 관리자가 있으면 신규 매장인데도 관리자가 이미 존재한다고 오판단함.
- **해결 쿼리 (특정 shop_id 한정 스코핑)**:
```sql
-- 반드시 URL 파라미터 또는 선택된 shop_id를 WHERE 절에 명시
SELECT id, name, is_admin, hourly_wage, status 
FROM staff 
WHERE shop_id = :targetShopId AND is_admin = true 
LIMIT 1;
```
- 결과가 0건이면 무조건 **대표 등록 모드**, 1건 이상이면 기존 대표 정보 수정 모드로 동작.

#### 3. Row Level Security (RLS) 정책 사양
- 멀티 테넌트 데이터 보호를 위해 모든 테이블에 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;` 적용.
- `system_admins`: 인증 확인용 API(Server Actions/Route Handler)를 통해 Service Role로 안전하게 조회 및 등록.
- `shops`: 메인 화면 조회를 위해 익명/공개 읽기(`SELECT`) 허용. 생성/수정은 시스템 관리자 세션 검증 후 허용.
- `staff`: 동일한 `shop_id`를 가진 사용자 간 본인 소속 매장 확인 허용. 타 매장 데이터 노출 방지.
- `attendance`: 직원은 본인의 `staff_id` 데이터만 조회/등록 가능, 플라워샵 대표는 본인 매장(`shop_id`) 소속 직원의 모든 근태 데이터 조회/수정 가능.

## 8. 품질 기준 (성능·보안·접근성)

### 품질 및 보안 검증 기준
1. **4자리 PIN 보안 및 정규식**:
   - 시스템 관리자, 대표, 직원의 모든 PIN 번호는 정확히 4자리 숫자(`^[0-9]{4}$`)여야 합니다.
   - 신규 등록 및 변경 시 '비밀번호 확인' 필드를 필수로 입력받아 100% 일치해야 저장 버튼이 활성화됩니다.
2. **멀티 테넌트 격리성**:
   - 모든 매장 데이터(`staff`, `attendance`)는 URL 파라미터의 `shop_id`와 인증된 세션의 `shop_id`를 교차 검증하여 타 매장 침범을 완전히 방지합니다.
3. **정확한 근무 시간 및 급여 산출 공식**:
   - 출근 기록 후 퇴근 전까지는 '근무 중' 상태로 표시되며 정산 집계에 포함되지 않습니다.
   - 일별 근무 분 = `퇴근 시간(분) - 출근 시간(분)` (휴게 시간 차감 없음).
   - 월 총 급여 산출: `Math.round((월 누적 근무 분 / 60) * staff.hourly_wage)` (원 단위 반올림 처리).

## 10. 테스트 계획

### 수용 테스트 시나리오 및 배포 검증 (Smoke Routes)

#### 1. 스모크 라우트 (Smoke Routes 검증)
배포 즉시 DB나 로그인 상태와 무관하게 200 상태 코드로 화면이 정상 렌더링되어야 하는 공개 경로:
- `GET /`: 전체 플라워샵 검색 및 진입 메인
- `GET /system-setup`: 시스템 관리자 최초 등록 화면
- `GET /shop/register`: 시스템 관리자 플라워샵 등록 진입 화면
- `GET /admin/setup`: 플라워샵별 관리자 등록/수정 화면
- `GET /signup`: 직원 가입 신청 화면

#### 2. 핵심 기능 수용 테스트 시나리오

- **테스트 1: 플라워샵별 관리자 독립 등록 (버그 검증)**
  - **Given**: 신규 등록된 플라워샵 B에 관리자가 아직 존재하지 않는다.
  - **When**: `/admin/setup?shop_id=B` 화면에 접속한다.
  - **Then**: "이미 해당 플라워샵에 관리자가 존재합니다" 오류가 뜨지 않고 빈 입력 폼이 렌더링되며, 4자리 PIN 2회 일치 입력 시 관리자로 신규 저장된다.

- **테스트 2: 직원 로그인 시 퇴사자 배제 검증**
  - **Given**: 플라워샵 A에 재직 직원 2명(`active`)과 퇴사 처리된 직원 1명(`resigned`)이 존재한다.
  - **When**: 플라워샵 A 메인(`/shop/A`)에서 직원 로그인 드롭다운을 확인한다.
  - **Then**: 재직 직원 2명의 이름만 노출되며, 퇴사한 직원은 선택지에서 완전히 숨겨진다.

- **테스트 3: 시간 피커 출퇴근 등록 및 급여 산출 검증**
  - **Given**: 시급 10,000원으로 책정된 직원이 로그인해 대시보드에 진입했다.
  - **When**: 특정 날짜를 선택하고 세련된 타임피커로 출근 09:30, 퇴근 18:30(총 9시간 = 540분)을 저장한다.
  - **Then**: 해당 날짜 근태 기록이 540분으로 계산되어 저장되고, 월 누적 예상 급여에 90,000원이 정확히 반영된다.

- **테스트 4: 근무 기록 및 급여 정산 화면 상태 뱃지 및 UI 검증**
  - **Given**: 관리자가 `/admin/attendance`에 접속했다.
  - **When**: 직원 목록을 조회한다.
  - **Then**: 대괄호(`[]`) 없는 텍스트 액션 버튼이 표시되고, 승인대기(주황), 재직(초록), 퇴사(회색) 뱃지가 올바르게 렌더링된다.
