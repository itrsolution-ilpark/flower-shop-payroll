## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
여러 개의 화원(플라워샵)을 각각 독립적으로 관리하며, 각 화원 소속 직원들의 일일 출퇴근 기록을 바탕으로 근무 시간을 산정하고 시급을 적용하여 월별 급여를 자동으로 계산 및 관리하는 멀티 테넌트 웹 프로그램입니다.

### 핵심 가치
- **화원별 독립 관리**: 화원(매장) 등록 후 해당 화원 소속의 관리자와 직원들을 분리하여 관리
- **화원별 관리자 설정**: 시스템 최초 접속 또는 화원 등록 시 해당 화원의 관리자 계정 생성 기능 제공
- **직원 생애주기 관리**: 직원이 가입 신청 후 관리자의 '승인'을 거쳐야 '재직(입사)' 상태가 되며, 퇴사 처리된 직원은 로그인 및 출퇴근 등록 제한
- **안전한 기록 및 인증**: 4자리 PIN 번호 등록/수정 시 2회 입력 검증(Validation) 및 PIN 인증을 통한 본인 출퇴근 기록 조회

### 주요 용어 정의
- **화원 (Shop)**: 독립된 근무지 단위
- **시급**: 시간당 임금 (원 단위, 정수)
- **근무 상태**: `pending`(승인 대기), `active`(재직/입사), `resigned`(퇴사)
- **관리자**: 특정 화원에 속하며 `is_admin=true` 속성을 가진 계정

## 2. 사용자와 사용 시나리오

### 사용자 역할

| 역할 | 설명 | 주요 권한 |
| --- | --- | --- |
| **비회원/신규직원** | 특정 화원에 새로 온 직원 | - 화원 선택 후 직원 회원가입 신청 (이름, 4자리 PIN 2회 입력, 희망 시급 입력, 상태=`pending`) |
| **직원 (재직자)** | 관리자 승인을 받은 직원 (`status='active'`) | - 화원 선택 및 4자리 PIN으로 로그인<br>- 일별 출근/퇴근 시간 등록 및 본인 근무 내역 조회 |
| **관리자** | 특정 화원의 대표 또는 점장 (`is_admin=true`) | - 화원 등록 및 관리자 계정 생성 (`/admin/setup`)<br>- 소속 화원의 신규 가입 직원 승인 및 상태 변경 (`active`/`resigned`)<br>- 직원별 시급 설정 및 출퇴근 기록 수정<br>- 월별/직원별 급여 집계 확인 |

### 사용자 시나리오
1. **화원 및 관리자 등록**: 메인 화면에서 화원을 신규 등록하거나, 이미 등록된 화원의 관리자 로그인 페이지로 진입하여 관리자 계정을 설정합니다.
2. **직원 가입 및 승인**: 직원이 해당 화원을 선택하고 회원가입을 신청하면 대기 상태(`pending`)가 되고, 해당 화원 관리자가 승인(`active`)합니다.
3. **출퇴근 등록 및 급여 정산**: 승인된 직원이 로그인하여 출퇴근을 기록하고, 관리자는 월말에 급여 집계표를 확인합니다.

## 5. 데이터 모델

### 데이터베이스 테이블 설계 (Supabase)

#### 1. `shops` (화원 정보)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `name` (text, 화원 이름, Not Null)
- `created_at` (timestamp, 기본값 `now()`)

#### 2. `staff` (직원 및 관리자 정보)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `shop_id` (uuid, `shops.id` 외래키, On Delete Cascade, Not Null)
- `name` (text, 직원 이름, Not Null)
- `pin_code` (text, 4자리 비밀번호, Not Null)
- `hourly_wage` (integer, 시급, Not Null, 기본값 10000)
- `is_admin` (boolean, 관리자 여부, 기본값 false)
- `status` (text, 직원 상태: `pending` 대기, `active` 재직, `resigned` 퇴사, 기본값 `'pending'`)
- `created_at` (timestamp, 기본값 `now()`)

#### 3. `attendance` (출퇴근 기록)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `staff_id` (uuid, `staff.id` 외래키, On Delete Cascade)
- `work_date` (date, 근무 일자, Not Null)
- `clock_in` (time, 출근 시간, Not Null)
- `clock_out` (time, 퇴근 시간, Nullable)
- `created_at` (timestamp, 기본값 `now()`)

### RLS(행 수준 보안) 정책
- `shops` 테이블: SELECT, INSERT 누구나 가능.
- `staff` 테이블: SELECT는 누구나 가능(화원별 로그인 드롭다운용), INSERT는 누구나 가능(회원가입/최초설정), UPDATE는 `is_admin=true` 관리자 또는 본인 허용.
- `attendance` 테이블: `status='active'`인 본인 직원 또는 `is_admin=true` 관리자만 접근 허용.

## 8. 품질 기준 (성능·보안·접근성)

### 품질 기준
- **입력 검증(Validation)**: PIN 번호 등록 및 수정 시 '비밀번호 확인' 필드와 일치하는지 프론트엔드에서 검증 후 제출 허용
- **상태 제어**: `pending` 또는 `resigned` 상태의 직원은 로그인 및 출퇴근 등록 차단 및 안내 메시지 노출
- **보안 및 예외 처리**: 
  - 화원별 관리자 설정(`/admin/setup`) 시, 이미 해당 화원에 `is_admin=true`인 직원이 존재하는지 서버 측에서 먼저 확인(Query)하고, 존재할 경우 400 Bad Request 및 안내 메시지("이미 해당 화원에 관리자가 존재합니다")를 반환하여 중복 등록 오류를 방지한다.
  - PIN 번호 불일치, 필수 값 누락 시 명확한 인라인 에러 메시지 제공

## 10. 테스트 계획

### 테스트 시나리오

- **시나리오 1: 화원 등록, 관리자 설정 및 직원 가입/승인**
  - **Given**: 시스템에 화원 및 관리자가 존재하지 않는다.
  - **When**: 사용자가 `/shop/register`에서 화원을 등록하고, `/admin/setup`에서 4자리 PIN을 2회 동일하게 입력하여 관리자를 생성한다.
  - **Then**: 해당 화원의 관리자 계정이 생성된다.
  - **When**: 신규 직원이 `/signup`에서 화원을 선택하고 PIN 번호를 2회 일치시켜 가입한다.
  - **Then**: `status='pending'` 상태로 가입되며, 관리자 페이지에서 승인 대기 목록에 노출된다.
  - **When**: 관리자가 해당 직원의 상태를 `active`(재직)로 변경한다.
  - **Then**: 해당 직원이 화원 선택 후 PIN 번호로 정상 로그인 및 출퇴근 등록이 가능해진다.

- **시나리오 2: 출퇴근 등록 및 급여 계산**
  - **Given**: `active` 상태인 직원이 로그인한 상태이다.
  - **When**: 출근 버튼을 누르고, 이후 퇴근 버튼을 누린다.
  - **Then**: `attendance` 테이블에 해당 일자의 `clock_in`과 `clock_out`이 기록되며, 마이페이지에서 총 근무 시간과 `시급 × 근무시간`으로 산정된 예상 급여가 계산되어 표시된다.
