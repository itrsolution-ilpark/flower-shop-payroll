## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
화원(플라워샵) 직원들의 일일 출퇴근 기록을 바탕으로 근무 시간을 산정하고, 시급을 적용하여 월별 급여를 자동으로 계산 및 관리하는 웹 프로그램입니다.

### 핵심 가치
- 직원: 본인 명의 등록 및 4자리 비밀번호(PIN)를 통한 안전한 출퇴근 기록 조회 및 수정
- 관리자: 전체 직원의 출퇴근 기록 검토, 수정 및 월별 급여 총액 확인

### 주요 용어 정의
- **시급**: 시간당 임금 (원 단위, 정수)
- **근무 시간**: 출근 시간부터 퇴근 시간까지의 시간 (휴게 시간 차감 없음)
- **관리자**: `is_admin=true` 속성을 가진 계정으로, 모든 직원의 데이터를 조회하고 보정할 수 있는 권한을 가진 사용자

## 2. 사용자와 사용 시나리오

### 사용자 역할

| 역할 | 설명 | 주요 권한 |
| --- | --- | --- |
| **직원** | 화원에서 일하는 파트타임/정직원 | - 본인 계정 생성 및 4자리 PIN 설정<br>- 일별 출근/퇴근 시간 등록 및 본인 기록 조회 |
| **관리자** | 화원 대표 또는 점장 | - 관리자 권한 계정(`is_admin=true`)으로 로그인<br>- 전체 직원 목록 관리 및 시급 설정<br>- 직원이 등록한 출퇴근 기록 수정/삭제<br>- 월별/직원별 근무 시간 및 급여 총액 집계 확인 |

### 사용자 시나리오
1. **직원 출퇴근 등록**: 직원이 사이트(` /`)에 접속하여 본인 이름을 선택하고 4자리 PIN을 입력해 로그인한 뒤, 오늘의 출근 시간과 퇴근 시간을 입력합니다.
2. **관리자 급여 정산**: 월말이 되면 관리자가 관리자 계정으로 `/admin`에 로그인하여 각 직원의 월별 총 근무 시간과 자동 계산된 급여를 확인하고 필요시 기록을 수정합니다.

| F-05 | 기록 보정 기능 | 관리자가 특정 직원의 잘못 입력된 출퇴근 기록 수정 | 관리자 | **Given** 관리자 권한이다.<br>**When** 특정 직원의 출근/퇴근 시간을 변경하고 저장한다.<br>**Then** 데이터가 즉시 반영된다. |
| F-06 | 시급 설정 | 직원별 시급 등록 및 변경 | 관리자 | **Given** 관리자 권한이다.<br>**When** 특정 직원의 시급을 수정한다.<br>**Then** 이후 급여 계산 시 변경된 시급이 적용된다. |

## 4. 화면과 주소(URL) 구성

### 화면 구성

| URL 경로 | 화면명 | 주요 UI 요소 |
| --- | --- | --- |
| `/` | 메인 / 로그인 화면 | 직원 선택 드롭다운, 4자리 PIN 입력 필드(`type="password"`, `maxLength=4`), 로그인 버튼, 회원가입 링크 |
| `/signup` | 직원 회원가입 화면 | 이름 입력 폼, 4자리 PIN 입력 폼, 시급 입력 폼, 가입 완료 버튼 |
| `/employee/dashboard` | 직원 마이페이지 | 출근/퇴근 시간 입력 폼, 이번 달 근무 내역 리스트(날짜, 출근, 퇴근, 근무시간), 예상 급여 총액 텍스트 |
| `/admin` | 관리자 대시보드 | 전체 직원 월별 급여 요약 표(이름, 총 근무시간, 시급, 총 급여), 월 선택 필터 |
| `/admin/attendance` | 관리자 근무 기록 관리 | 직원별 출근/퇴근 시간 수정/삭제 모달 포함 테이블 |
| `/admin/staff` | 직원 관리 화면 | 직원 목록 테이블, 시급 수정 폼, PIN 초기화 버튼 |

## 5. 데이터 모델

### 데이터베이스 테이블 설계 (Supabase)

#### 1. `staff` (직원 정보)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `name` (text, 직원 이름, Not Null)
- `pin_code` (text, 4자리 비밀번호, Not Null)
- `hourly_wage` (integer, 시급, Not Null, 기본값 10000)
- `is_admin` (boolean, 관리자 여부, 기본값 false)
- `created_at` (timestamp, 기본값 `now()`)

#### 2. `attendance` (출퇴근 기록)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `staff_id` (uuid, `staff.id` 외래키, On Delete Cascade)
- `work_date` (date, 근무 일자, Not Null)
- `clock_in` (time, 출근 시간, Not Null)
- `clock_out` (time, 퇴근 시간, Nullable)
- `created_at` (timestamp, 기본값 `now()`)

### RLS(행 수준 보안) 정책
- `staff` 테이블: 익명 및 인증된 사용자 모두 SELECT 허용(직원 선택용), INSERT는 누구나 가능(회원가입), UPDATE는 본인 또는 `is_admin=true` 관리자 허용.
- `attendance` 테이블: `staff_id`가 본인이거나 `is_admin=true`인 관리자만 SELECT, INSERT, UPDATE, DELETE 허용.

## 8. 품질 기준 (성능·보안·접근성)

### 품질 기준
- **보안**: 4자리 PIN은 평문 저장 또는 간단한 인증 대조 수행, 관리자 페이지는 `is_admin` 플래그 세션 검증 필수
- **성능**: 모바일 환경에서 페이지 로딩 시간 2초 이내
- **예외 처리**: 퇴근 시간이 출근 시간보다 빠를 경우 "퇴근 시간은 출근 시간보다 빠를 수 없습니다." 경고 팝업 노출

## 10. 테스트 계획

### 테스트 시나리오 (수용 기준)
- **시나리오 1: 직원 로그인 및 출퇴근 등록**
  - **Given**: 직원이 가입되어 있다.
  - **When**: `/`에서 이름을 선택하고 4자리 PIN을 입력 후 로그인하여 출근/퇴근 시간을 입력한다.
  - **Then**: `/employee/dashboard`에 정상적으로 기록이 반영되고 급여가 계산된다.
- **시나리오 2: 관리자 급여 확인**
  - **Given**: 관리자 계정으로 로그인했다.
  - **When**: `/admin` 페이지를 연다.
  - **Then**: 등록된 모든 직원의 월별 근무 시간 합계와 급여 총액이 정확히 계산되어 표시된다.
