## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
화원(플라워샵) 직원들의 일일 출퇴근 기록을 바탕으로 근무 시간을 산정하고, 시급을 적용하여 월별 급여를 자동으로 계산 및 관리하는 웹 프로그램입니다.

### 핵심 가치
- **관리자 최초 설정**: 시스템 최초 접속 시 관리자 계정 생성 기능 제공
- **직원 생애주기 관리**: 직원이 가입 신청 후 관리자의 '승인'을 거쳐야 '재직(입사)' 상태가 되며, 퇴사 처리된 직원은 로그인 및 출퇴근 등록 제한
- **안전한 기록 관리**: 4자리 PIN 번호 인증을 통한 본인 출퇴근 기록 조회 및 등록, 관리자의 수정/보완 권한

### 주요 용어 정의
- **시급**: 시간당 임금 (원 단위, 정수)
- **근무 상태**: `pending`(승인 대기), `active`(재직/입사), `resigned`(퇴사)
- **관리자**: `is_admin=true` 속성을 가진 계정으로, 직원 승인, 시급 설정 및 전체 데이터 보정 권한 보유

## 2. 사용자와 사용 시나리오

### 사용자 역할

| 역할 | 설명 | 주요 권한 |
| --- | --- | --- |
| **비회원/신규직원** | 화원에 새로 온 직원 | - 직원 회원가입 신청 (이름, 4자리 PIN, 시급 입력, 상태=`pending`) |
| **직원 (재직자)** | 관리자 승인을 받은 직원 (`status='active'`) | - 4자리 PIN으로 로그인<br>- 일별 출근/퇴근 시간 등록 및 본인 근무 내역 조회 |
| **관리자** | 화원 대표 또는 점장 (`is_admin=true`) | - 최초 시스템 설정 시 관리자 계정 생성 (`/admin/setup`)<br>- 신규 가입 직원 승인 및 상태 변경 (`active`/`resigned`)<br>- 직원별 시급 설정 및 출퇴근 기록 수정<br>- 월별/직원별 급여 집계 확인 |

### 사용자 시나리오
1. **최초 관리자 생성**: 사이트에 처음 접속하여 `/admin/setup`을 통해 관리자 계정을 생성합니다.
2. **직원 가입 및 승인**: 신규 직원이 회원가입을 하면 대기 상태(`pending`)가 되고, 관리자가 관리자 대시보드에서 이를 확인 후 승인(`active`)합니다.
3. **출퇴근 등록 및 급여 정산**: 승인된 직원이 로그인하여 출퇴근을 기록하고, 관리자는 월말에 급여 집계표를 확인합니다.

## 5. 데이터 모델

### 데이터베이스 테이블 설계 (Supabase)

#### 1. `staff` (직원 정보)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `name` (text, 직원 이름, Not Null)
- `pin_code` (text, 4자리 비밀번호, Not Null)
- `hourly_wage` (integer, 시급, Not Null, 기본값 10000)
- `is_admin` (boolean, 관리자 여부, 기본값 false)
- `status` (text, 직원 상태: `pending` 대기, `active` 재직, `resigned` 퇴사, 기본값 `'pending'`)
- `created_at` (timestamp, 기본값 `now()`)

#### 2. `attendance` (출퇴근 기록)
- `id` (uuid, Primary Key, 기본값 `gen_random_uuid()`)
- `staff_id` (uuid, `staff.id` 외래키, On Delete Cascade)
- `work_date` (date, 근무 일자, Not Null)
- `clock_in` (time, 출근 시간, Not Null)
- `clock_out` (time, 퇴근 시간, Nullable)
- `created_at` (timestamp, 기본값 `now()`)

### RLS(행 수준 보안) 정책
- `staff` 테이블: SELECT는 누구나 가능(로그인 드롭다운용), INSERT는 누구나 가능(회원가입/최초설정), UPDATE는 `is_admin=true` 관리자 또는 본인 허용.
- `attendance` 테이블: `status='active'`인 본인 직원 또는 `is_admin=true` 관리자만 접근 허용.

## 10. 테스트 계획

### 테스트 시나리오

- **시나리오 1: 최초 관리자 설정 및 직원 가입/승인**
  - **Given**: 시스템에 관리자가 존재하지 않는다.
  - **When**: 사용자가 `/admin/setup`에서 관리자 계정 정보를 입력하고 생성한다.
  - **Then**: `is_admin=true`인 관리자 계정이 생성되고, 이후 `/admin/setup` 접근이 차단된다.
  - **When**: 신규 직원이 `/signup`에서 이름, 4자리 PIN, 시급을 입력하고 가입한다.
  - **Then**: `status='pending'` 상태로 가입되며, 관리자 페이지에서 승인 대기 목록에 노출된다.
  - **When**: 관리자가 해당 직원의 상태를 `active`(재직)로 변경한다.
  - **Then**: 해당 직원이 PIN 번호로 정상 로그인 및 출퇴근 등록이 가능해진다.

- **시나리오 2: 출퇴근 등록 및 급여 계산**
  - **Given**: `active` 상태인 직원이 로그인한 상태이다.
  - **When**: 출근 버튼을 누르고, 이후 퇴근 버튼을 누른다.
  - **Then**: `attendance` 테이블에 해당 일자의 `clock_in`과 `clock_out`이 기록되며, 마이페이지에서 총 근무 시간과 `시급 × 근무시간`으로 산정된 예상 급여가 계산되어 표시된다.
