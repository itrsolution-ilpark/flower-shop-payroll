## 1. 프로젝트 개요 (한눈에 보기)

### 프로젝트 목적
‘플라워샵 근무 관리’는 다수의 플라워샵에 대해 시스템 관리자, 플라워샵 관리자(대표), 플라워샵 직원의 3단계 권한을 분리하여 직원 가입 승인, 출퇴근 관리, 시급/월급 기반 급여 계산, 데이터 다운로드 기능을 제공하는 종합 업무 웹 프로그램입니다.

### 사용자 역할 및 주요 권한
1. **시스템 관리자 (2명 이상 등록 가능, 비밀번호 6자리)**
   - 프로그램 전체 총괄 관리 및 추가 시스템 관리자 등록
   - 플라워샵 등록, 정보 수정, 상태 관리(활성 `active` / 비활성 `inactive`)
   - 플라워샵별 관리자 및 직원 목록 현황 통합 조회
2. **플라워샵 관리자/대표 (플라워샵당 2명 이상 등록 가능, 비밀번호 6자리)**
   - 소속 플라워샵 신규 직원 가입 승인(신청 상태 → 승인) 및 퇴사 처리
   - 직원별 급여 형태(시급 / 월급) 및 계산 단위(시간 / 분 단위) 설정 관리
   - 직원별 출퇴근 기록 보완/수정, 월별 급여 정산 관리
   - 월별 직원 근무 현황 및 급여 데이터 CSV 다운로드
   - 관리자 본인 정보 수정 및 소속 플라워샵의 추가 관리자 등록
3. **플라워샵 직원 (비밀번호 4자리)**
   - 등록된 활성 플라워샵 대상 가입 신청(최초 관리자가 존재하는 플라워샵만 신청 가능)
   - 승인 후 로그인하여 본인 일별 출근/퇴근 시각 등록 및 수정
   - 월별 근무 기록 및 급여 산정 내역 조회, 본인 정보 수정

### 안전한 서버 중심 DB 아키텍처 (Neon PostgreSQL)
- 모든 데이터 읽기/쓰기는 **Next.js Server Actions** 내부에서 Neon PostgreSQL 풀을 통해 실행되며, 브라우저에 `DATABASE_URL` 등 DB 자격 증명이 절대 노출되지 않습니다.
- 세션은 서명된 HttpOnly 쿠키(`APP_SESSION_SECRET`)로 안전하게 관리됩니다.

| 시스템 관리자 | 이름 + 비밀번호 | **숫자 6자리** | 시스템 관리자 최초/추가 등록, 플라워샵 등록·수정·비활성화, 플라워샵별 관리자/직원 목록 조회 |

### 상태값 정의 (Enum)
1. **플라워샵 상태 (`shops.status`)**
   - `active` (등록/활성): 정상 운영 상태. 플라워샵 관리자 및 직원의 로그인 및 가입 신청 가능
   - `inactive` (비활성): 시스템 관리자를 제외한 해당 플라워샵 소속 관리자 및 직원의 로그인 및 모든 접근이 차단됨
2. **직원 상태 (`staff.status`)**
   - `pending` (가입신청): 직원이 가입을 신청한 초기 상태(화면 표시: '승인대기'). 로그인 불가
   - `approved` (승인): 플라워샵 관리자가 승인한 상태. 정상 로그인 및 출퇴근 기능 이용 가능
   - `resigned` (퇴사): 플라워샵 관리자가 퇴사 처리한 상태. 로그인 및 신규 기록 차단, 과거 정산 데이터는 보존
3. **급여 형태 (`pay_type`) 및 계산 기준 (`time_unit`)**
   - `hourly` (시급): 일별 출퇴근 시간에 대해 시급 적용. 계산 기준은 `minute`(분 단위 정밀 정산) 또는 `hour`(시간 단위 올림/내림 정산)
   - `monthly` (월급): 고정 월급여 적용 (월 중간 적용 시 일할 정산)

| F-07 | 시급 직원의 일별 출퇴근 기록 | 승인된 시급 직원은 날짜(기본 오늘), 출근 시각, 퇴근 시각을 등록 및 수정합니다. 총 근무 시간은 분 단위로 자동 계산되며 퇴근 시각은 출근 시각보다 늦어야 합니다. | **Given** 승인된 시급 직원 세션이 있다. **When** 유효한 날짜와 출퇴근 시간을 저장한다. **Then** `attendance`에 저장되고 근무 시간(분)이 계산되어 화면에 반영된다. |

## 4. 화면과 주소(URL) 구성

### 전체 화면 흐름도
`메인 화면 (/)` → `로그인 화면 (/login)` 또는 `직원/관리자 가입 신청 (/signup)` → 권한별 대시보드 (`/system/dashboard`, `/shop-admin/dashboard`, `/employee/dashboard`)

## 5. 데이터 모델

### 데이터베이스 스키마 (Neon PostgreSQL 전체 실행 DDL)

```sql
-- 1. 기존 테이블 정리
DROP TABLE IF EXISTS auth_attempts CASCADE;
DROP TABLE IF EXISTS attendance CASCADE;
DROP TABLE IF EXISTS compensation CASCADE;
DROP TABLE IF EXISTS staff CASCADE;
DROP TABLE IF EXISTS shop_admins CASCADE;
DROP TABLE IF EXISTS shops CASCADE;
DROP TABLE IF EXISTS system_admins CASCADE;

-- 2. 시스템 관리자 테이블 (복수 등록 지원, 6자리 비밀)
CREATE TABLE system_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  pin_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. 플라워샵 테이블 (상태: active, inactive)
CREATE TABLE shops (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name TEXT NOT NULL UNIQUE,
  status TEXT NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 4. 플라워샵 관리자 테이블 (플라워샵별 복수 등록 지원, 6자리 비밀)
CREATE TABLE shop_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_hash TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (shop_id, name)
);

-- 5. 플라워샵 직원 테이블 (상태: pending, approved, resigned, 4자리 비밀)
CREATE TABLE staff (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id UUID NOT NULL REFERENCES shops(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  pin_hash TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending'
    CHECK (status IN ('pending', 'approved', 'resigned')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  resigned_at TIMESTAMPTZ,
  UNIQUE (shop_id, name)
);

-- 6. 직원 급여 조건 테이블 (시급/월급, 시간/분 단위 정산)
CREATE TABLE compensation (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  pay_type TEXT NOT NULL CHECK (pay_type IN ('hourly', 'monthly')),
  time_unit TEXT NOT NULL DEFAULT 'minute' CHECK (time_unit IN ('minute', 'hour')),
  amount_krw INTEGER NOT NULL CHECK (amount_krw > 0),
  effective_from DATE NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (staff_id, effective_from)
);

-- 7. 출퇴근 근무 기록 테이블 (시급 직원용 일별 기록)
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  work_date DATE NOT NULL,
  clock_in TIME NOT NULL,
  clock_out TIME NOT NULL,
  total_minutes INTEGER NOT NULL CHECK (total_minutes > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (staff_id, work_date),
  CHECK (clock_out > clock_in)
);

-- 8. 로그인 시도 차단 테이블 (브루트포스 방지)
CREATE TABLE auth_attempts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  identity_hash TEXT NOT NULL,
  attempted_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  succeeded BOOLEAN NOT NULL DEFAULT FALSE
);

-- 9. 성능 최적화 인덱스
CREATE INDEX idx_shops_status ON shops(status);
CREATE INDEX idx_shop_admins_shop_id ON shop_admins(shop_id);
CREATE INDEX idx_staff_shop_status ON staff(shop_id, status);
CREATE INDEX idx_compensation_staff ON compensation(staff_id, effective_from DESC);
CREATE INDEX idx_attendance_staff_date ON attendance(staff_id, work_date);
CREATE INDEX idx_auth_attempts_identity ON auth_attempts(identity_hash, attempted_at DESC);
```

## 8. 품질 기준 (성능·보안·접근성)

### 계산 규칙 및 보안 무결성
1. **비밀번호 규칙**
   - 시스템 관리자 & 플라워샵 관리자: 반드시 **숫자 6자리** (`^[0-9]{6}$`)
   - 플라워샵 직원: 반드시 **숫자 4자리** (`^[0-9]{4}$`)
   - 모든 비밀번호는 단방향 bcrypt 해시 형태로만 DB에 저장되며 평문 저장 절대 금지
2. **플라워샵 비활성화 시 보안 통제**
   - `shops.status = 'inactive'`일 경우, 해당 플라워샵의 모든 관리자와 직원은 로그인 시도가 즉시 거부되며 기존 발급된 세션 쿠키도 요청 즉시 무효화됩니다.
3. **급여 계산 알고리즘**
   - **시급(`hourly`)**:
     - `time_unit = 'minute'`: `(총 근무 분 / 60) * 시급`, 원 단위 반올림 (`Math.round`)
     - `time_unit = 'hour'`: `Math.floor(총 근무 분 / 60) * 시급` (시간 단위 정산)
   - **월급(`monthly`)**:
     - 기본적으로 해당 월 고정액 지급. 월 중간 시작일 적용 시 해당 월 전체 일수 대비 유효 일수로 일할 계산
4. **CSV 데이터 다운로드 형식**
   - 파일명: `flower_payroll_[YYYY_MM].csv`
   - UTF-8 with BOM 인코딩 (엑셀에서 한글 깨짐 방지)
   - 헤더: `직원명,상태,급여형태,계산단위,적용금액(원),해당월 총 근무시간(분),지급예정액(원)`

## 9. 배포와 운영

### 배포 및 DB 설정 절차
1. **Neon PostgreSQL 인스턴스 준비**: Neon 콘솔 프로젝트 생성을 완료하고 해당 프로젝트의 SQL Editor에서 `schema.sql` 스크립트를 실행하여 모든 테이블과 인덱스를 구제합니다.
2. **Neon Database Connection String 복사**: Neon 콘솔의 Dashboard / Connection Details에서 제공되는 `Pooled Connection String` (`DATABASE_URL`)을 복사합니다.
3. **Vercel Environment Variables 등록**:
   - `DATABASE_URL`: 복사한 Neon DB 연결 URL 설정
   - `APP_SESSION_SECRET`: 32자 이상의 임의 보안 암호화 문자열 등록
4. **Vercel 재배포**: GitHub 저장소를 Vercel 프로젝트에 연동하고 Deploy 실행.
5. **배포 후 스모크 테스트**: 지정된 5개 라우트 (`/`, `/login`, `/signup`, `/system/login`, `/system/setup`)의 정상 접근성 및 동작을 검증합니다.

## 10. 테스트 계획

### 테스트 계획 및 시나리오

1. **Smoke 검증 (공개 경로 HTTP 200)**
   - `GET /`: 메인 화면 정상 로드, 상단 고정 배너 및 시스템 관리자 링크 렌더링 확인
   - `GET /login`: 플라워샵 드롭다운, 관리자/직원 탭 정상 렌더링 확인
   - `GET /signup`: 직원 가입 신청 및 최초 관리자 개설 탭 렌더링 확인
   - `GET /system/login`: 시스템 관리자 로그인 카드 렌더링 확인
   - `GET /system/setup`: 시스템 관리자 0명일 때 최초 등록 폼 렌더링 확인

2. **시스템 관리자 및 플라워샵 비활성화 테스트**
   - **Given** 시스템 관리자로 로그인되어 있다.
   - **When** 특정 플라워샵 상태를 `inactive`로 변경한다.
   - **Then** 해당 플라워샵 소속 관리자 및 직원이 로그인을 시도할 때 즉시 차단 메시지가 표시된다.

3. **비밀번호 규칙 검증**
   - **Given** 직원 또는 관리자 가입/등록 화면이다.
   - **When** 관리자 비밀번호에 4자리나 영문자를 입력하거나, 직원 비밀번호에 6자리를 입력한다.
   - **Then** 유효성 검사에서 차단되고 정해진 자릿수(관리자 6자리, 직원 4자리) 입력 안내가 표시된다.

4. **직원 승인 및 정산 계산 검증**
   - **Given** 직원이 가입하여 `pending` 상태이다.
   - **When** 관리자가 시급 10,000원, 분 단위(`minute`) 정산으로 승인하고 직원이 9시간 30분(570분) 근무를 기록한다.
   - **Then** 관리자 정산 화면에서 `(570 / 60) * 10,000 = 95,000원`으로 정확히 계산된다.

5. **CSV 다운로드 무결성 검증**
   - **Given** 관리자가 정산 페이지에서 특정 월을 선택했다.
   - **When** CSV 다운로드 버튼을 클릭한다.
   - **Then** 응답 헤더에 UTF-8 with BOM이 포함되며 직원의 이름, 근무시간, 지급예정액이 정확한 컬럼 형식으로 출력된다.
